# 🥚 기프트클릭 (GiftClick)

금계란을 **터치로 직접**, 또는 **자동 클릭 모드**로 두들겨 최대 **50,000원** 상품을 뽑는
클릭형 햅테크 풀스택 데모 앱입니다.

## 주요 기능

- 🔐 **인증** — 이메일/비밀번호 회원가입·로그인 (bcrypt 해시 + JWT httpOnly 쿠키 세션, 미들웨어 보호)
- 🥚 **금계란 게임** — 6~12번 두들기면 부화, 가중치 랜덤 상품 추첨, 자동 깨기 모드, 매일 자정 깨기권 충전
- 🎁 **상품 관리 CRUD** — 등록/수정/삭제/노출 토글, 가치·가중치·재고 설정, 카테고리 필터/검색
- 🎀 **기프트 보관함 CRUD** — 핀코드 발급/조회, 사용 완료 처리, 메모·정보 수정, 만료 자동 처리, 직접 등록
- 🧾 **깨기 내역** — 모든 터치 로그, 날짜별 그룹핑, 개별/전체 삭제
- 📊 **대시보드** — 주간 활동 차트, 연속 출석 스트릭, XP 레벨, 랭킹, 최근/최고 당첨
- 📺 **광고 시청 리워드** — 광고 끝까지 본 후 깨기권 자동 지급, 쿨타임/일일 한도 서버 강제, 예상 수익 견적 원장, AdSense 실전 배너 지원
- ✨ **UX 폴리시** — 낙관적 업데이트(SWR), 로딩 스켈레톤, 빈 상태, 토스트, 컨페티, 반응형(모바일 드로어)

## 🎓 학생 개발자를 위한 기프트 API 가이드

**현실 체크**: 기프티콘·현금 지급의 "정식 API"(기프티엘, KT알파, 카카오 선물하기, 토스페이먼츠 지급대행, 오픈뱅킹)는
전부 **사업자등록 + 기업 계약**이 필요해요. 그래서 이 앱은 3단계 전략입니다:

| 단계 | 모드 (`GIFTCON_PROVIDER`) | 언제 쓰나 |
|---|---|---|
| 1️⃣ 개발·테스트 | `sandbox` (기본) | 키 없이 기프티엘과 동일한 발급/회수/동기화 플로우 재현 |
| 2️⃣ 실물 소액 운영 | `manual` | 학생이 직접 운영 — 당첨 시 **📦 발송 관리**에 쌓이고 카톡 선물하기/토스 송금으로 직접 전달 |
| 3️⃣ 실전 연동 | `giftiel` | **부모님 사업자**로 기프티엘 파트너 계약 후 API 키 투입 |
| 4️⃣ **완전 자동 현금** | `paypal` | 부모님 PayPal Business + Payouts 승인 시, 당첨 즉시 **자동 송금** (운영자 손 안 거침) |

### 💸 PayPal 자동 송금 (가장 자동화된 현금 지급)

당첨과 동시에 당첨자 이메일로 자동 송금되고, 운영자가 할 일은 예치금 관리뿐이에요.

1. 부모님이 PayPal **Business** 계정 개설 (만 18세 이상, 본인인증)
2. PayPal에 **Payouts 기능 승인** 신청 (사업 용도 심사 — 보통 며칠 소요)
3. 개발 중엔 `PAYPAL_ENV=sandbox`로 PayPal 공식 샌드박스에서 가짜 계정끼리 테스트
4. 당첨자는 **내 정보 → PayPal 수령 이메일** 등록 (미성년 당첨자는 부모님 계정 등 상의)
5. 실패(미등록/네트워크)하면 자동으로 **📦 수동 발송 큐**로 넘어가서 놓치는 당첨이 없어요

> ⚠️ KRW는 PayPal Payouts 미지원이라 `PAYPAL_KRW_RATE`(환산비율)로 USD 등으로 변환해 송금합니다.
> 환전 수수료가 발생하니 소액 다건에는 토스 송금이 더 유리해요.

> **"그냥 바로 주는 곳"은 없나요?** — 사업자/계약 없이 개인이 **결제 즉시 발송**할 수 있는 건 API가 아니라
> 소비자용 서비스(💬 카카오톡 선물하기, 🎟 배민 상품권몰, 📚 컬쳐랜드 문상 즉구, 💚 네이버 선물하기)예요.
> `manual` 모드의 발송 모달에 이들 **바로가기 버튼이 내장**돼 있어 당첨 상품명 검색까지 한 번에 갑니다.

### 부모님 사업자로 기프티엘 실전 전환하는 법

> 사업자등록증 **사진만으로는 부족해요.** 부모님이 아래 단계에 "직접" 참여해야 합니다.

1. 부모님이 기프티엘 파트너센터에 **기업 회원가입** (사업자등록증 사본 📷 제출 — 사진 OK)
2. 부모님 **대표 본인 인증** (대표 휴폰/아이핀)
3. **전자계약 서명** + 필요 시 예치금(상품 비용 선불) 충전
4. 담당자(본인) 계정에 발급된 **API 키**를 `giftclick/.env`에 설정:
   ```env
   GIFTCON_PROVIDER=giftiel
   GIFTIEL_API_BASE=기프티엘_문서의_API_호스트
   GIFTIEL_API_KEY=발급받은_키
   GIFTIEL_PARTNER_CODE=파트너_기업코드
   ```
5. 서버 재시작 → 상품 관리 페이지 연동 패널이 **✅ 실전 연동**으로 바뀌면 끝!
   (꼬이면 `GIFTCON_PROVIDER=sandbox`로 되돌리면 즉시 복구)

### ⚠️ 현금 입금에 대한 주의

- 현금 이체 API(토스페이먼츠 지급대행/오픈뱅킹)도 **사업자 필요** — 개인은 불가
- 포인트·경품을 **현금으로 환전 가능**하게 만들면 환금성 때문에 **사행행위 규제 리스크**가 커져요
- 당첨자의 **계좌번호를 앱 DB에 저장하지 마세요** (개인정보). 카톡으로 주고받고, 앱에는 발송 메모만
- 학생 운영은 **소액·자발적 이벤트 경품** 범위로! 애매하면 부모님과 상담 필수

## 📺 광고 수익화 (시청 리워드 + AdMob/AdSense)

유저가 광고를 끝까지 본 만큼 기록이 쌓이고, 깨기권 보상 + **예상 수익 견적**이 자동 기록됩니다.

- **광고 시청 리워드**: 1회 끝까지 시청 → 깨기권 +2장 (서버가 쿨타임 60초·하루 10회 강제)
- **수익 원장**: 시청 1건당 예상 수익을 자동 누적 (`ad_views` 테이블, `ADS_EST_CPM_KRW`로 CPM 조정)
- **환경 자동 감지**: 브라우저 → 5초 테스트 광고 / 안드로이드 앱 → **진짜 AdMob 보상형 광고**

### 🧭 광고 ID 두 종류 (혼동 주의)

| 경로 | ID 형식 | 쓰이는 곳 | 설정 |
|---|---|---|---|
| **앱 AdMob** | `ca-app-pub-XXXX~YYYY`(앱ID), `ca-app-pub-XXXX/ZZZZ`(광고단위) | 안드로이드/iOS 앱 보상형·배너 | `NEXT_PUBLIC_ADMOB_*` + Capacitor 앱 ([docs/ANDROID.md](docs/ANDROID.md)) |
| **웹 AdSense** | `ca-pub-XXXX` | 브라우저 웹사이트 배너 | `NEXT_PUBLIC_ADSENSE_CLIENT/SLOT` |

> ⚠️ `ca-app-pub`(애드몹) ID는 웹 `<ins>` 광고에 넣어도 작동하지 않아요! 반대도 마찬가지.

### 🛡️ SSV (서버 측 검증) — 돈이 붙는 순간 조작 방지

`POST /api/ads/complete`는 브라우저 요청이라 위조 가능성이 있지만, **쿨타임/일일 한도가 서버에 고정**되어 피해가 하루 20장으로 제한됩니다.
상용 단계에서는 AdMob 콘솔에 리워드 URL(`https://도메인/api/ads/ssv`)을 등록하면 **구글 서버가 직접 지급을 호출**해 클라이언트 조작이 원천 차단됩니다 (ECDSA 서명 검증, `transaction_id` 중복 지급 방지 내장).

### 💰 "내 통장에 수익 100% 꽂기" 현실 정리

| 항목 | 내용 |
| --- | --- |
| 누가 주나? | 앱이 아니라 **Google(AdMob/AdSense)이 정산** (앱 DB엔 견적치만 저장) |
| 100% 가능? | ❌ 광고주가 낸 돈의 **게시자 몫은 약 68%**(나머지는 Google). 다만 *게시자 몫의 100%*가 정산 계좌에 자동 입금되는 건 맞아요 |
| 계정 자격 | **만 18세 이상** → 부모님이 가입하고 **부모님 통장**으로 정산 (사업자로도 가능) |
| 지급 시점 | 매월 결산 후 **익월 21~26일**, 잔액 **$100 이상**일 때 |
| 세금 | 부모님 이름으로 수입 처리 — 무조건 부모님과 상의 |
| 미성년자가 할 수 있는 것 | 앱 개발·운영·광고 붙이기까지 전부 본인이 하고, 돈은 부모님 계정/통장에 꽂히게 하는 구조 |

> ⚠️ 팁: 방문자가 없으면 수익도 0원. 광고 버튼을 눌러주는 친구들이 매일 들어와야 의미가 생겨요.
> 실제 정산액은 AdMob/AdSense 대시보드에서 확인하고, 앱 안 숫자는 견적(추정)치입니다.

## 🤝 기프티콘 API 연동 (기프티엘)

당첨될 때마다 **프로바이더 어댑터**를 통해 쿠폰(핀코드)을 발급합니다. 상품 관리 페이지 상단의 연동 패널에서 상태와 카탈로그 동기화를 관리할 수 있어요.

| 항목 | 내용 |
|---|---|
| 프로바이더 | `lib/giftcon/` — `GiftconProvider` 인터페이스 + `sandbox` / `giftiel` 구현체 |
| 기본 동작 | **샌드박스 모드** — 키 없이 기프티엘과 동일한 발급·회수·카탈로그 플로우 재현 |
| 실전 전환 | `.env.example`을 `.env`로 복사 후 `GIFTCON_PROVIDER=giftiel` + `GIFTIEL_API_KEY`/`GIFTIEL_PARTNER_CODE` 입력 → 서버 재시작 |
| 발급 실패 시 | 사용자 흐름은 유지 — 로컬 핀으로 대체 발급하고 실패 이력만 `giftcon_issues`에 기록 |
| 동기화 | `POST /api/giftcon/sync` — 발급사 카탈로그를 상품 풀에 upsert (카테고리/이모지 자동 추론) |
| 회수 | 보관함에서 기프트 삭제 시 발급 쿠폰 회수(cancel) best-effort 호출 |

> ⚠️ 기프티엘의 실제 엔드포인트·필드명은 파트너 개발자 문서 기준으로 확정이 필요합니다.
> 모든 경로(`GIFTIEL_PATH_*`)와 응답 필드는 방어적 파싱 + env 오버라이드로 되어 있어 문서 확인 즉시 맞출 수 있습니다.

### 관련 API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/giftcon/status` | 연동 모드/준비 여부/발급 통계/마지막 동기화 |
| GET | `/api/giftcon/goods` | 발급사 상품 카탈로그 조회 |
| POST | `/api/giftcon/sync` | 카탈로그 → 상품 풀 동기화 |
| GET | `/api/ads/status` | 광고 모드/쿨타임/일일 시청 수/예상 수익(관리자는 전체 합계) |
| POST | `/api/ads/complete` | 광고 시청 완료 → 깨기권 지급 + 수익 원장 기록 |
| GET | `/api/ads/ssv` | AdMob SSV 콜백 (구글 서버 검증 후 지급, 서명/중복 차단) |

## 게임 경제

- 터치 1회 = 깨기권 1장 소모, +10 XP (부화 시 +500 XP)
- 8% 확률로 터치하더라도 깨기권 복원(별 반사)
- 부화 시 `weight` 가중치 기반 상품 추첨 → 재고 차감 → 핀코드 기프트 즉시 발급 (30일 유효)
- 깨기권: 매일 자정(KST) 5장 자동 충전 + 게임 화면의 미션 보상(30분 쿨타임 +3장)
